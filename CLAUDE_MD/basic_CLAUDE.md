# 規約

## コミュニケーション
- ⚠️ **ユーザーに表示されるテキストは、すべて日本語で書く。**
  最終回答だけでなく、**ツール実行の合間の短い進捗報告・前置き・見出し・箇条書きも例外なく日本語。**
  英語で書いてよいのはコード・コミットメッセージ・ソースコード中のコメントのみ。
- 不明点は勝手に判断せず、必ずユーザーに確認する

## Claudeの行動指針
- 破壊的・不可逆な操作（ファイル削除、force push等）の前はユーザーに確認する
- エラーが発生した場合は同じ操作をリトライせず、原因を調査・分析してから対処する

## コーディングスタイル
- インデントは2スペース（ただしGoなど言語慣習がタブの場合はその慣習に従う）
- 命名規則は言語の慣習に従う（例: Python はスネークケース、JS/TS はキャメルケース）
- ソースコード中のコメントは英語で書く（特に指示がある場合を除く）
- 型注釈・型定義は可能な限り付与する
- APIキー・パスワード等の秘密情報のハードコードは禁止。環境変数または設定ファイルを使用する

## ドキュメント
- ドキュメントは日本語で書く（特に指示がある場合を除く）
- 図の表現にはMermaidを推奨する

## コマンド実行
- コマンドを実行するときは必ず`cd`コマンドで絶対パスを用いて作業ディレクトリに移動してから実行する

## テスト
- 新機能・バグ修正にはテストを追加する
- テスト実行後は結果をユーザーに報告する

## git関連
- `git add .`や`git add -A`は禁止。個別のファイルを指定するのを基本とし、`git add -u`は他の作業と並行していない等、無関係な変更が混ざらないと確信できる場合に限り使う（新規ファイルは個別指定）
- `git commit`はユーザーの許可を得てから行う（都度の許可に限らず、セッション内で一律の許可を求めてもよい）
- 特別な指示がない限りは`git push`は禁止（ユーザーが自分で実行する）
- `--force`オプションの使用は原則禁止
- 機密ファイル（`.env`等）やビルド成果物（`dist/`, `build/`, `*.pyc`等）は`git add`しない（`.gitignore`で管理する）
- `.gitignore`が存在しない場合は作成する
- ファイル・ディレクトリのリネームや移動は`mv`ではなく`git mv`を使う（履歴を正しく追跡させるため）
- git管理下のファイルを削除する場合は`rm`ではなく`git rm`を使う（削除がステージされ、`git status`で意図通り認識されるため）
- コミットメッセージはConventional Commits形式を使用する
  - `feat:` 新機能, `fix:` バグ修正, `docs:` ドキュメント, `refactor:` リファクタリング, `test:` テスト, `chore:` その他
- コミットメッセージ本文は英語で書く

## Python
- 外部ライブラリを使う場合は `python -m venv env` で仮想環境を作成する
- すでに `env/` が存在する場合はそれを使用する
